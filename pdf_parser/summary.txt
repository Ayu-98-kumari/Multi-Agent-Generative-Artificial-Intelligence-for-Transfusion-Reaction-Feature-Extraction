===============================================================================
 pdf_parser — PROJECT SUMMARY
 Faithful PDF -> structured JSON for clinical surveillance protocols
 (built & validated against: bv-hv-protocol-current.pdf — CDC NHSN
  Hemovigilance Component Protocol v3.0, 34 pages)
===============================================================================

GOAL
-----
Convert a well-structured medical PDF into a faithful, structured JSON
representation for a downstream RAG pipeline. The two failure modes actively
guarded against are (1) SILENT OMISSION of content and (2) TABLE FRAGMENTATION.
Inference provider is Groq (model: qwen/qwen3.6-27b, a vision + reasoning model).


===============================================================================
 1. PIPELINE WORKFLOW
===============================================================================

  INPUT PDF
     |
     v
  +--------------------------------------------------------------+
  | PASS 1 — SKELETON  (skeleton.py, deterministic, NO LLM)      |
  |  - PyMuPDF: TOC + heading regex -> sections & page spans      |
  |  - inventory: Table N. / Figure N. + fingerprinted unlabeled |
  |    tables (archived reaction tables, version-history table)  |
  |  - per-page normalized text (headers/footers stripped)       |
  |  - page -> section map                                       |
  |  -> writes skeleton.json (inspectable, reusable backbone)     |
  +--------------------------------------------------------------+
     |  (skeleton = both VLM context AND validation checklist)
     v
  +--------------------------------------------------------------+
  | PASS 2 — VISION  (vision_parser.py, Groq VLM, page by page)  |
  |  - render page -> PNG -> base64 image                         |
  |  - prompt = system.md + page_user.md with per-page context:  |
  |      section, expected tables/figures, layout hint,          |
  |      CONTINUATION hint (skeleton-driven, sequential)         |
  |  - temperature=0, JSON mode, reasoning_effort="none"         |
  |  - retry+backoff on 429/transient; truncation detector;      |
  |    json_validate_failed handled as incomplete -> retry       |
  |  -> per-page PageParse (fixed schema), cached per page        |
  +--------------------------------------------------------------+
     |
     v
  +--------------------------------------------------------------+
  | STITCH  (stitching.py)                                       |
  |  - merge cross-page TABLE fragments into one table           |
  |  - merges ONLY on continuation signals (continued/_from,     |
  |    repeated label, "(cont'd)"); page-adjacency bound         |
  |  - e.g. Table 8 fragments p19-22 -> one table page_span[19,22]|
  +--------------------------------------------------------------+
     |
     v
  +--------------------------------------------------------------+
  | ASSEMBLE  (pipeline.py)                                      |
  |  - group blocks into sections by start-page -> section map   |
  |  - assign stable block_ids (s<sec>-b<idx>)                   |
  |  - build Document (title, version, pages, parsed_on, ...)    |
  +--------------------------------------------------------------+
     |
     v
  +--------------------------------------------------------------+
  | VALIDATE  (validation.py) — deterministic acceptance gate    |
  |  1 schema  2 inventory  3 coverage  4 structure  (HARD)      |
  |  5 golden facts (FLAG)   -> report names check + section/page |
  +--------------------------------------------------------------+
     |
     v
  FINAL <stem>.json  +  PASS/FAIL validation report
  (exit code non-zero on hard failures)

  Driven by cli.py:  python -m pdf_parser.cli --input <pdf> --output <json>

 4. JSON SCHEMA (shallow outline; page is METADATA, not a level)
===============================================================================

 Document(title, version, source_filename, total_pages, parsed_on, sections[])
   Section(section_number, title, page_span[start,end], content[])
     ProseBlock  : type, subheading?, text, page, block_id
     TableBlock  : type, label, caption, page_span, columns[], rows[{cells}],
                   notes[], footnotes[], continued_from, continued, block_id
     FigureBlock : type, label, caption, description, page, abbreviations?,
                   block_id

 Notes: blocks stay FLAT under a section (one level). subheading is a label on a
 prose block, not a nested container. block_id (s<sec>-b<idx>) aids RAG citation
 and validation traceability.

 5. VALIDATION GATE
===============================================================================

 #  | Check                | Severity | What it enforces
 ---|----------------------|----------|-----------------------------------------
 1  | Schema conformance   | HARD     | output validates against Pydantic models
 2  | Inventory complete   | HARD     | each skeleton table (17) + figure (3)
    |                      |          | appears EXACTLY ONCE after stitching,
    |                      |          | matched BY PAGE; extras flagged as likely
    |                      |          | unstitched fragments
 3  | Coverage round-trip  | HARD     | TOKEN-level, order-independent recall of
    |                      |          | Pass-1 text >= 0.95 (anti-omission net;
    |                      |          | baseline = extractor text, not absolute)
 4  | Structural invariants| HARD     | tables >=1 row, no stray cell columns;
    |                      |          | block pages within section span + correct
    |                      |          | parent; non-decreasing reading order;
    |                      |          | figures have non-empty descriptions
 5  | Golden facts         | FLAG     | specific clinical values survived (below)

 9. HOW TO RUN
===============================================================================

 # Pass 1 only — inspect skeleton before any VLM spend
 python -m pdf_parser.cli --input bv-hv-protocol-current.pdf --skeleton-only

 # Cheap isolated first VLM call — one page
 python -m pdf_parser.cli --input bv-hv-protocol-current.pdf --single-page 19

 # Full run -> writes <stem>.json + prints validation report
 python -m pdf_parser.cli --input bv-hv-protocol-current.pdf -v

 # Tests
 python -m pytest pdf_parser/tests/ -q

 Flags: --skeleton-only, --single-page N, --skip-validation, --force-skeleton,
        --no-cache, --coverage-threshold F, -v / -vv
 Caching: skeleton.json + per-page VLM results cached under
          <stem>_pdfparser/ ; re-runs are cheap and resume on transient 429s.
